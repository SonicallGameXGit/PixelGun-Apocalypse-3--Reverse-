Names with a `__<path_id>` suffix are same-named distinct objects.

## Audio

- Every clip is `m_CompressionFormat = 7` (AAC), stored as an MP4 container in `sharedassets0.resource` / `resources.resource` and referenced by `m_Resource` (source, offset, size).
- Music: only **`muzica lobby.m4a`** (mono, 44.1 kHz, 22.76 s). No other music track exists in this build (**observed**: all 48 clips listed). If in-game music existed, it was streamed from elsewhere or belongs to a different version (**unknown**).

## `assets/data/` format

Generated by `tools/extract/export_world.py`. Conventions:

- **References**: `{ "ref": "<serialized file>:<path_id>" }`, plus `"asset": "<path under assets/>"` when the target was published (textures, audio, meshes, fonts, sprites). `null` = no reference. Refs are stable identifiers into the original build.
- **Floats**: float32 values in the shortest decimal form that round-trips to the identical float32 (lossless).
- **Hierarchies** are flat, depth-first `nodes` lists: each node has `ref`, `name`, `active`, `layer`, `tag`, `parent` (ref or null), `children` (refs) and `components`.
- **Components**: built-in components carry their full Unity typetree as `data` (`m_GameObject`, `m_Children`, `m_Father` removed as redundant). MonoBehaviours carry `script`, `enabled`, `fields` and `fields_complete`.

| Path | Content |
|------|---------|
| `scenes/<Scene>.json` | 20 scenes: scene settings (`RenderSettings`, `LightmapSettings`, ...), all GameObjects |
| `prefabs/resources/<Resources path>.json` | prefabs loadable via `Resources.Load` / `PhotonNetwork.Instantiate` (players, bots, weapons pickups, menus, ...) |
| `prefabs/resources.assets/*.json`, `prefabs/sharedassets0.assets/*.json` | other prefab roots (bullets, impacts, explosions, ...) |
| `resources.json` | Resources path → object(s) |
| `materials.json` | all materials (shader name, textures with scale/offset, floats, colors, keywords) keyed by ref |
| `textures.json` | per published texture: size, format, mip count, filter (point/bilinear/trilinear), wrap U/V, aniso, colour space |
| `scriptable/<Script>/*.json` | standalone ScriptableObjects (`PhotonServerSettings`, GUISkins, ad settings) |
| `settings/*.json` | project settings: `PhysicsManager`, `TimeManager`, `InputManager`, `TagManager`, `QualitySettings`, `PlayerSettings`, ... |
| `animations/AnimationClip/*.json`, `animations/AnimatorController/*.json` | raw typetrees (Mecanim muscle-clip encoding, not yet decoded to curves) |

### MonoBehaviour decoding

Typetrees for scripts are stripped from the build. `tools/extract/mono_decode.py` rebuilds them from the IL2CPP class layouts (`dump.cs` field order/types/attributes + `NotSerialized` flags from `DummyDll`) using Unity 2018.3 serialization rules. **All 1,772 MonoBehaviours with a script decode byte-exact** (every byte consumed). The other 57 are empty "Missing Script" placeholders (32 bytes, no data). Findings that the decoder had to account for (**observed**):

- `[System.NonSerialized]` is an IL field flag; Il2CppDumper's `dump.cs` omits it, DummyDll keeps it.
- Non-`[Serializable]` element types → the whole list is absent (no count written).
- 2018.3 `GUIStyleState` has no `m_ScaledBackgrounds`; `GUIStyle` packs bool pairs (`wordWrap`+`richText`, `stretchWidth`+`stretchHeight`) with one alignment. Script bools align individually.

### Maps

Map geometry lives in the scene files as `VBSP_Object.model_N` meshes with `MeshCollider`s, i.e. the maps were converted from **Source-engine BSP** maps (**inferred** from names). Scenes also hold `Team A/B SpawnPoints`, the `__Room` network object (`PhotonView`, `RoomMultiplayerMenu`, `MultiplayerChat`, `WhoKilledWho`), camera and lights. Players, bots, weapons and effects are prefabs under `prefabs/resources/`.

## Not yet extracted

- **Animations**: 85 clips are Mecanim muscle clips (streamed/dense/constant encoding, bindings by path CRC); decode into per-bone curves → glTF. The 233 legacy `Animation` components reference null clips (**unknown** why; check whether legacy clips were stripped or are resolved by name at runtime).
- **Skinned meshes / skeletons**: OBJ has no bones/weights; export characters and all meshes to glTF (keeps UV2, vertex colors, skinning).
- Particle systems: data is in the component typetrees; needs a renderer-side reimplementation.
