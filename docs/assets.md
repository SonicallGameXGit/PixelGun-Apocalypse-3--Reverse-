# Assets

Pipeline: `tools/extract/` (see its README). Output: `assets/` + `assets/manifest.json` (each file → original Unity serialized file + `path_id`, name, size/audio info).

## Published (2026-11-07, CrazyGames build)

Since 2026-11-07 `assets/` holds the **CrazyGames build** (Unity 5.3.5, `docs/crazygames-build.md`), the build the online client plays against. The Build-7 extraction (Unity 2018.3) is in git history (commit `7e55c83` and earlier) and reproducible with the same tools; how the two differ: `docs/crazygames-build.md`, "Assets".

Excluded: Unity built-in resources (`unity_default_resources`, `unity_builtin_extra`), except the built-in `Arial` font (`unity_default_resources:10102`, see below); 12 empty 0×0 `Font Texture` objects (runtime dynamic font atlases, nothing to extract).

Names with a `__<path_id>` suffix are same-named distinct objects.

## Audio

- Every clip is `m_CompressionFormat = 7` (AAC), stored as an MP4 container in `sharedassets0.resource` / `resources.resource` and referenced by `m_Resource` (source, offset, size).
- Music: only **`muzica lobby.m4a`** (mono, 48 kHz in this build, 44.1 kHz in Build-7; 22.76 s). No other music track exists in either build (**observed**: all 48 clips listed). If in-game music existed, it was streamed from elsewhere or belongs to a different version (**unknown**).
- The 48 clips are the same sounds as Build-7's, encoded separately (waveform correlation 0.87-1.0 at zero lag; some sample rates differ: 22,050 / 44,100 / 48,000 Hz).

## Fonts: licensing note

The built-in font every `OnGUI` default style uses is Unity's `Arial` (`unity_default_resources:10102`), which is in fact **Liberation Sans 2.00.1** (SIL Open Font License 1.1). `publish_assets.py` publishes it as `assets/fonts/Arial.ttf` (allow-list `BUILTIN_ALLOWED`) with its licence in `assets/fonts/OFL-LiberationSans.txt`, which the clean step keeps.

Some fonts bundled by the original developers are commercial third-party fonts: `ebrima.ttf` / `A A A A A ebrimabd.ttf` (Microsoft Ebrima; Build-7 also had `_-_IMPACT.ttf`, Impact by Monotype). Redistribution may not be permitted; decide before publishing the repo.

## `assets/data/` format

Generated by `tools/extract/export_world.py`. Conventions:

- **References**: `{ "ref": "<serialized file>:<path_id>" }`, plus `"asset": "<path under assets/>"` when the target was published (textures, audio, meshes, fonts, sprites). `null` = no reference. Refs are stable identifiers into the original build.
- **Floats**: float32 values in the shortest decimal form that round-trips to the identical float32 (lossless).
- **Hierarchies** are flat, depth-first `nodes` lists: each node has `ref`, `name`, `active`, `layer`, `tag`, `parent` (ref or null), `children` (refs) and `components`.
- **Components**: built-in components carry their full Unity typetree as `data` (`m_GameObject`, `m_Children`, `m_Father` removed as redundant). MonoBehaviours carry `script`, `enabled`, `fields` and `fields_complete`.
- **Tags**: a node's `tag` is Unity's number: 0 Untagged, 1 Respawn, 2 Finish, 3 EditorOnly, 5 MainCamera, 6 Player, 7 GameController; custom tags start at 20000 in `settings/TagManager.json` order (20000 `Metal`, 20001 `Blood`, ...).
- **Non-finite floats**: Python's `json` writes them as the bare tokens `NaN`, `Infinity`, `-Infinity` (particle curve slopes in the effect prefabs). They are not strict JSON; the client's `assets::load_json` reads them as strings and `f32_of` converts them back.

| Path | Content |
|------|---------|
| `scenes/<Scene>.json` | 20 scenes: scene settings (`RenderSettings`, `LightmapSettings`, ...), all GameObjects |
| `prefabs/resources/<Resources path>.json` | prefabs loadable via `Resources.Load` / `PhotonNetwork.Instantiate` (players, bots, weapons pickups, menus, ...) |
| `prefabs/resources.assets/*.json`, `prefabs/sharedassets0.assets/*.json` | other prefab roots (bullets, impacts, explosions, ...) |
| `resources.json` | Resources path → object(s) |
| `materials.json` | all materials (shader name, textures with scale/offset, floats, colors, keywords) keyed by ref |
| `textures.json` | per published texture: size, format, mip count, filter (point/bilinear/trilinear), wrap U/V, aniso, colour space |
| `scriptable/<Script>/*.json` | standalone ScriptableObjects (`PhotonServerSettings`, GUISkins, ad settings) |
| `settings/*.json` | project settings: `PhysicsManager`, `TimeManager`, `InputManager`, `TagManager`, `QualitySettings`, `PlayerSettings`, ... |
| `animations/AnimationClip/*.json`, `animations/AnimatorController/*.json` | raw typetrees; gameplay clips are legacy curve clips (see below), read directly by the client |
| `skins/<model stem>.json` | skinning of a published skinned mesh (`export_skins.py`): `bind_poses` (row-major 4×4, mesh → bone space), `bone_name_hashes`, `root_bone_name_hash`, per-vertex `bone_indices`/`bone_weights` (×4, Unity vertex order = OBJ vertex order, Unity mesh space) |

### MonoBehaviour decoding

Typetrees for scripts are stripped from the build. `tools/extract/mono_decode.py` rebuilds them from the IL2CPP class layouts (`dump.cs` field order/types/attributes + `NotSerialized` flags from `DummyDll`) using the serialization rules of the build's Unity version. **CrazyGames (5.3): all 1,752 MonoBehaviours with a script decode byte-exact** (every byte consumed; 21 have no script). Build-7 (2018.3): all 1,772 byte-exact, plus 57 empty "Missing Script" placeholders (32 bytes, no data). Findings that the decoder had to account for (**observed**):

- `[System.NonSerialized]` is an IL field flag; Il2CppDumper's `dump.cs` omits it, DummyDll keeps it.
- Non-`[Serializable]` element types → the whole list is absent (no count written).
- 2018.3 `GUIStyleState` has no `m_ScaledBackgrounds`; `GUIStyle` packs bool pairs (`wordWrap`+`richText`, `stretchWidth`+`stretchHeight`) with one alignment. Script bools align individually.
- Unity 5.3 `AnimationCurve` keyframes have 4 floats (time, value, inSlope, outSlope): the `weightedMode`/`inWeight`/`outWeight` fields came with 2018.1. The decoder takes the version from the serialized files (`unity_compat.unity_version`, major.minor; the built-in resources may differ in patch level, 5.3.4p1).

### Unity 5.3 serialization (CrazyGames build)

What the extractor and the client handle beyond the 2018.3 layout (**observed** in the typetrees):

- `GameObject.m_Component` is a list of (classID, PPtr) pairs; texture settings have one `m_WrapMode`; material property maps are keyed by `{name}` (FastPropertyName), normalized to plain names by `export_world.py`.
- Shaders have no `m_ParsedForm`: the name is the `Shader "..."` line of `m_Script`, the programs an LZ4 `m_SubProgramBlob` that UnityPy 1.25.4 reads big-endian; `unity_compat.export_shader` parses it little-endian (sub-program version 201509030).
- Sprites without a packed atlas keep the old vertices/indices mesh; `extract_assets.py` crops their `textureRect` from the texture.
- `ParticleSystem` (Shuriken) has the 5.3 module layout and `TrailRenderer` start/end widths and five colours; the client converts both on load (`docs/gameplay/particles.md`, "Unity 5.3 layout").
- The legacy particle components (`EllipsoidParticleEmitter`, `ParticleAnimator`, `ParticleRenderer`) still exist; the shotgun smoke uses them (`docs/gameplay/particles.md`, "Legacy particles").

### Maps

Map geometry lives in the scene files as `VBSP_Object.model_N` meshes with `MeshCollider`s, i.e. the maps were converted from **Source-engine BSP** maps (**inferred** from names). Scenes also hold `Team A/B SpawnPoints`, the `__Room` network object (`PhotonView`, `RoomMultiplayerMenu`, `MultiplayerChat`, `WhoKilledWho`), camera and lights. Players, bots, weapons and effects are prefabs under `prefabs/resources/`.

## Animations and skins

- **Animations** (re-checked 2026-11-06, **observed**): every gameplay clip under `resources.assets` is a **legacy** clip (`m_Legacy: true`). Its data is in the plain curve arrays (`m_RotationCurves` quaternion, `m_PositionCurves`, `m_ScaleCurves`; Hermite keys with `inSlope`/`outSlope`, `weightedMode` 0), keyed by transform **path string** (e.g. `Root_jnt/Hips_jnt/...`). `m_MuscleClip` is empty for them, so no muscle/CRC decoding is needed. Only the 8 UI clips in `sharedassets0` (`Normal`, `Highlighted`, `Pressed`, ...) are Mecanim clips, driven by the 43 `Animator`s in `Main`/`Credits`. The 233 `Animation` components in `prefabs/resources` **do** reference their clips (`m_Animations` refs resolve to `animations/AnimationClip/<name>__<file>_<path_id>.json`); the earlier "null clips" note was wrong.
- **Skinned meshes**: the OBJ keeps geometry; `data/skins/` holds bind poses and weights (6 meshes: `Box005`, `Box005__166`, `Base_mesh`, `SpecialForces_03_mesh`, `Terrorist_01_mesh`, `Terrorist_02_mesh`). Bones are the `SkinnedMeshRenderer.m_Bones` transforms in the prefab JSON. Playback and skinning rules: `docs/gameplay/animation.md`.
- **Unity built-in meshes** (`unity_default_resources`: Cube 10202, Cylinder 10206, Plane 102, Sphere 23) are referenced by many prefabs but are Unity's, so they stay unpublished; the client regenerates them (`primitives.rs`).
